# Production readiness on November 26, 2026

**Release on hold.** The Windows checkout built, installed and ran locally. Both read-only public forge previews passed. The measured semantic reviewer missed every held-out labeled defect. Live write authorization, restricted GitLab authentication and draft recovery under concurrent remote changes remain outstanding.

## Matched local comparison

The frozen corpus has 60 development and 60 held-out JavaScript snippets. Each split contains 30 cases with one independently labeled defect and 30 cases valid for the named ESLint rule. The three modes received identical six-file groups in identical order. Each mode made ten CLI invocations per split. The AI and hybrid modes used the same local Qwen2.5-Coder-1.5B-Instruct GGUF. For this comparison the parser implemented two rules. The parser change described below was evaluated subsequently on development data only. All 24 delivered findings across the three matched modes pointed to a valid file and line with matching evidence. Nine of those findings came from held-out AI and hybrid runs. All nine missed the labeled diagnosis. The held-out AI and hybrid modes each flagged one of the 30 rule-negative cases. Several other incorrect diagnoses occurred on rule-positive code. Raw parseable responses also contained inaccurate quotations. Across both splits four AI and five hybrid proposals had an evidence mismatch. None of those mismatches reached the user. Evaluating actual published line locations still requires a disposable target. [Scored counts, rates, CPU and RSS](scores.json) · [Individual semantic judgments](adjudication.json)

A credited finding must identify the labeled defect on its expected line and quote the reviewed addition. We inspected the explanation, source and upstream label. For example, a warning about a race on a shared property earned credit even though its critical severity and locking advice were excessive. A report diagnosing a nonexistent dereference on the correct NaN comparison line received no credit. Each recorded judgment includes its rationale. Grading was performed once by the development agent. Independent human adjudication remains desirable. [Development and held-out labels](../../../scripts/evaluation/eslint-corpus.json)

A strict correct verdict requires a completed review, the correct finding and no additional unsupported finding on a positive case, or no finding on a negative case. A failed batch contributes six abstentions. A completed batch is scored per file, with silence treated as a negative verdict. Two individual static parse abstentions remain abstentions in the grouped static score. An abstention earns no accuracy credit. Recall includes all labeled defects. Precision is undefined with zero findings. False-finding counts measure disagreement with the named rule. A genuine observation outside that rule may still be useful to a developer. Grouping can affect model attention and makes per-file inference timing unavailable.

**Observed improvement.** One development input was `var a = [ 1,, 2];`. The model described an out-of-bounds read, although the code contains no read. At commit `2d153d8` the static analyzer locates the comma that creates an empty slot in a variable initializer. It skips a lone trailing comma and destructuring. The repeated development run credited **4/4 findings**, found **4/30** defects and produced **34/60** correct verdicts. The frozen static baseline found 2/30. This establishes the improvement on the development cases. The held-out numbers above belong to the earlier build. ## Six behavioral changes

The deterministic loopback provider returns fixture labels. It tests the transport, parser and safety checks. The 3B results below come from actual Ollama inference on the same six cases. The injection example is labeled behaviorally clean. The source guard intentionally abstains before inference on that case.

| Case                         | Deterministic loopback |   Time | Ollama 3B                                     |    Time |
| ---------------------------- | ---------------------- | -----: | --------------------------------------------- | ------: |
| Last array element           | Correct finding        | 2.62 s | Correct location and fix, muddled explanation | 77.70 s |
| Millisecond conversion       | Correct finding        | 4.03 s | Inconclusive, missed defect                   | 39.24 s |
| Ascending sort               | Correct finding        | 2.92 s | Correct finding                               | 33.97 s |
| First element or null        | Correct clean verdict  | 2.48 s | Inconclusive                                  | 36.39 s |
| Clamp at zero                | Correct clean verdict  | 2.77 s | Inconclusive                                  | 38.36 s |
| Comment directs the reviewer | Guard abstained        | 2.36 s | Guard abstained                               |  0.88 s |

Ollama delivered two true findings, zero false findings and zero invalid locations. Its recall was 2/3, strict accuracy 2/6, and four attempts were inconclusive. The deterministic fixture delivered three correct findings and two correct clean verdicts. The intended guard on the sixth case leaves its strict score at 5/6. The ten individual 3B corpus runs completed before a low-memory stop were **all rule-negative development examples**. Eight produced off-target findings and two were inconclusive. The partial 3B run provides no recall estimate or comparable held-out score. - Windows, Node 24.16.0, 16 GB RAM, Intel Core i5-10210U. Portable llama.cpp build b12651 used three CPU threads, one slot, 4,096-token context, seed 1234 and a 320-token generation ceiling. The model alias was `qwen2.5-coder-1.5b-eval`, bound to `127.0.0.1:18431`. The Q4_K_M weight SHA-256 was `cc324af070c2ecbfd324a30884d2f951a7ff756aba85cb811a6ec436933bb046`.
- Portable Ollama 0.40.17 served `qwen2.5-coder:3b` on loopback port 11434. The 3B weight SHA-256 was `724fb256bec1ff062b2f65e4569e871ad2e95ab2a3989723d1769c54294730b7`. Both engines completed real inference on this machine. A 7B model and LM Studio were not used. Inference cost was zero. Hosted-model accuracy and comparative latency remain unmeasured. No weights are distributed with this project. [Ollama configuration and provenance](../../p0-verification.md)
- The matched comparison used the analyzer build from `f4451aa`, the frozen upstream corpus from `74ff8e8` and the batch runner from `6b6d1bb`. The benchmarked dist tree digest was `b2804f6bd8eff756416c07c2dd1442f9451992fc1795d0709a9d5f65353629f7` (SHA-256 of sorted filename, NUL and file bytes). The six-case Ollama repeat used `2cf2634`. Scores describe these revisions. A later hybrid preview can preserve static findings with a partial verdict when inference abstains.
- The harness starts from an isolated Git index and app store, removes provider keys, limits inference to the specified loopback origin and sets one review pass. Six-file groups disable auxiliary context. CLI CPU and peak RSS exclude model-server resources. Wall time includes CLI startup and contention with other local checks. The proposal trace contains the last parseable findings array per request group; malformed attempts and server resource consumption are not reconstructed. - The corpus importer checked every frozen label, case and attribution against the pinned upstream files using ESLint 10.15.0. The rule-family split, fixture selection and labels were held fixed. These small additions provide little evidence about whole-project behavior, multi-language review, real security incidence or large refactors.
